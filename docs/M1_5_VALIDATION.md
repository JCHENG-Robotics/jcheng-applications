| ROS | none; no DDS, no `rclpy`, no device |
| Repository code | imported from `src/`; `runner.py` delegates to `core/` with an unchanged public API |

**Dependency finding.** py_trees is not dependency-free: it requires
`pydot>=1.4`, which pulled `pydot 4.0.1` and `pyparsing 3.3.3`. pydot is used
for rendering, not for ticking, but it is a hard install-time dependency and
must be in the licence review and the lock. pydot 4.x is newer than the version
py_trees 2.6 was developed against; rendering compatibility is untested and is
not used by this design.

## 2. Checks

The probe runs eleven checks. All eleven passed in this session.

| ID | Check | Result | Key observation |
|---|---|---|---|
| M15-A | candidate metadata and transitive dependency | PASS | 2.6.0, BSD-3-Clause, requires `pydot>=1.4` |
| M15-B | non-blocking `RUNNING` leaf | PASS | 16 ticks over 0.30 s, max tick gap 20 ms, `initialise` once |
| M15-C | sequence memory | PASS | the second child was not ticked until the first succeeded |
| M15-D | `stop` calls `terminate(INVALID)` | PASS | terminal status `INVALID`, worker drained |
| M15-E | late future after stop | PASS | late completion flagged, leaf `INVALID`, run `INDETERMINATE` |
| M15-F | hung worker | PASS | tick loop kept 15 ticks over 0.30 s; daemon worker did not block exit |
| M15-G | app-side stop race | PASS | late `COMPLETED` did not advance the plan; 1 submission; `INDETERMINATE` |
| M15-H | single worker | PASS | peak concurrency 1 |
| M15-I | nominal gateway-call parity | PASS | 2/2 submissions, identical keys and parameters, 0 stops |
| M15-J | independent supervisor thread | PASS | deadline stop issued on `m15-supervisor`, one submission, late result, `WAITING_FOR_OPERATOR` |
| M15-K | failure-path differential, 11 cases | PASS | state, command sequence/keys, step outcomes/reason codes/bus, stop count and stop-error presence all match the linear runner |

M15-I compares the **nominal** path. M15-K adds the failure matrix: success,
unverified completion, rejected at step 1 and 2, aborted, timeout, unknown,
submit exception, safety latch mid-run, stop failure and a malformed result.
After the extraction both drivers call the same `StepExecutor` and `classify`
from `jcheng_applications.core`; the tree side no longer carries a decision
mirror.

M15-K itself does not compare the full `RunReport` object. That gap is closed
by T-C06 in `tests/test_tree_regression.py`: the linear and tree engines run
the same 12 scripted cases against the same mock gateway with a fixed clock,
and the **complete `RunReport` dataclasses must be equal** (state, steps, abort
reason, stop error, operator/session, timestamps). T-C06 is **verified**;
evidence is `evidence/20261126_t_c06/`. Deadline/cancellation has no linear
equivalent and is covered separately by `tests/test_tree_runtime.py`.

## 3. What this supports

- `py_trees` 2.6 can express the design's leaf protocol: `update()` returns
  `RUNNING`, the tick loop is not blocked, and `initialise()` is not repeated
  for a running leaf.
- `terminate(INVALID)` is a usable cancellation hook: it fires on stop and can
  attach a late-completion handler.
- A late completion after a stop can be made structurally non-success at the
  leaf, which is the app-side counterpart of the system C2 requirement.
- One `ThreadPoolExecutor(max_workers=1)` gives the single in-flight property
  the design needs.
- The Shared Execution Core is extractable without changing the linear
  runner's public API or the 89 v0.1.0 tests; preflight, command, submission,
  classification and stop-once now have one implementation.
- A supervisor thread can own the deadline and issue the stop on its own
  thread; the late result never advances the plan (M15-J).
- The shared core matches the linear runner across eleven failure cases
  (M15-K), and the production tree engine matches the linear engine's full
  `RunReport` across 12 cases (T-C06).

## 4. What this does not support

- The probe's supervisor is a probe class; the production supervisor is in
  `tree/runtime.py` and is covered by `tests/test_tree_runtime.py`. The tree
  engine is opt-in and not the default.
- The probe itself has no gateway, no HTTP and no lease; its stop sink is a
  fake. Those paths are covered by the M3 and tree-runtime tests.
- T-C06 is verified for the 12-case matrix, but it is still a mock matrix, not
  hardware.
- No hardware and no physical-stop claim. A Python worker thread cannot be
  killed; a wedged transport call still needs a socket timeout and, if wedged,
  a process restart.
- pydot 4.x rendering compatibility is untested; rendering is not used.
- The probe is a script, not a packaged test. It is run manually under an
  isolated venv and is not part of the repository gate.
